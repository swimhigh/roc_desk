roc_desk：代码树与架构说明

面向人工阅读的 Tauri 开发者桌面客户端源码地图。内容根据仓库结构及实现入口整理；刻意排除了构建产物和依赖树。

1. 系统概览

桌面应用外壳

src-tauri 负责进程启动、应用状态、Tauri Command 注册、领域服务、持久化，以及本地与远程主机集成。

前端

src-web 负责 React 界面渲染。组件通过 Zustand Store 和 Service 包装层访问能力；Service 是 Tauri IPC 的边界。

远程访问

ssh/ 提供 SSH 与 SFTP。可选的 agent/ 独立程序提供经 TLS 保护的 Windows 远程服务协议。

以工作区为中心

本地根目录和远程根目录统一表示为工作区。FileOps 抽象让 Explorer、编辑器、搜索和编程工具可以跨传输方式工作。

主要调用边界：React 组件 → Zustand Store → services/*.ts → Tauri commands/*.rs → 领域模块 / AppState → 本地文件系统、SSH/SFTP、Agent、数据库或 AI Provider。组件不应直接调用 Tauri。

3. src-tauri：桌面端后端

src-tauri/src/lib.rs 是后端组合根。它初始化便携数据目录、日志与 panic 捕获、数据库连接池/迁移、各类 Manager 和 Connection Pool，随后将它们放进 AppState 并注册 Tauri Command。它还区分单实例启动器进程和独立拉起的模块窗口进程。

入口与横切文件
路径职责
main.rs精简的二进制入口，委托给库入口。
lib.rs应用启动、Tauri Builder/Plugin、状态初始化、Command 注册、便携数据与日志设置。
state.rsAppState：供 Command 注入的共享 Manager、Pool、Repository、编程会话与运行时服务。
error.rs面向前端操作的类型化错误转换。
windows_context_menu.rsWindows 原生右键菜单集成。
commands/：前端 IPC 门面

Command Handler 获取状态、校验/转换请求参数、调用领域行为并序列化结果。业务逻辑应放在领域模块中，而非该 IPC 边界中。

5. 远程 Agent 与共享协议

protocol/

传输无关的共享请求/响应类型。lib.rs 定义操作和错误码；frame.rs 定义带 Stream ID 与帧类型的长度前缀二进制帧。

agent/

产出部署到远程 Windows 主机的 roc_desk_agent.exe。它独立运行，不会成为主桌面程序的运行时依赖。

Agent 文件职责
main.rs运行、配对、服务安装/卸载、状态和初始化等 CLI 命令。
server.rsTLS Listener、连接生命周期、协议帧分派和响应流。
handlers/fs.rs、exec.rs、search.rs、shell.rs服务端文件、进程、内容搜索和交互式 Shell 操作。
auth.rs、cert.rs、config.rs配对认证、自签名证书管理和配置。
pathguard.rs、audit.rs、selftest.rs、service.rs路径授权、审计记录、诊断和 Windows 服务管理。

信任过程是显式的：Agent 流量使用 TLS 与证书指纹信任流程，概念上与 SSH 主机密钥 TOFU 平行；配对 Token 用于首次关联授权。

6. codex-engine：Codex 集成边界

此小型 crate 将 vendored OpenAI Codex 运行时依赖限制在单一边界内。根 Cargo 工作区排除了 vendor/codex，因为该源码本身是另一个 Cargo 工作区。主 Tauri crate 依赖此适配层，而不是直接依赖 Codex 内部 crate。

文件职责
lib.rsEngine、Execution Target 和 Exec Server 的公开导出。
engine.rs核心 Chat/Codex Engine 集成与事件桥接。
exec_target.rs执行目标抽象。
exec_server.rsExec Server JSON-RPC 集成，将 Codex 执行映射到 roc_desk 的本地/SSH/Agent 目标。

7. 持久化、迁移与安全

db/pool.rs 创建 SQLite Pool；db/migrate.rs 执行迁移；db/repo/ 包含各持久化领域的 Repository（连接、主机信任、工作区、Provider、编程历史、权限、传输、MCP 和浏览历史）。

迁移范围存储内容
0001–0003基础设置、连接数据和 FTS5 日志搜索 Schema。
0005–0009审计记录、工作区、AI Provider、浏览历史和编程历史。
0010–0013连接协议/选项、编程权限规则、MCP Server 与 Agent 证书信任。
0014–0017传输日志/字节数、按工作区保存的 SFTP 路径状态和详细编程消息。
安全边界。连接密码/密钥和 AI Provider Secret 存放在操作系统密钥环，而不是 SQLite。SSH 主机密钥和 Agent 证书使用含用户确认的首次使用信任模型。编程命令 Guard 会阻止或确认高风险执行，外发 AI 请求前还会脱敏。

8. 关键执行流程

启动与窗口模型
  1. lib.rs::run() 解析便携 .rock_desk 数据目录、设置滚动日志并安装 panic 捕获。
  2. 它解释 --mode/--open 参数，区分单实例启动器与模块窗口进程。
  3. 它打开/迁移数据库，初始化 Repository/Manager/Pool，创建 AppState 并注册 Command。
  4. 前端挂载 App.tsx，读取模式和状态，再展示首页外壳或相应模块。
打开和编辑工作区
  1. UI 打开本地根目录，或选择已保存的远程连接与目录。
  2. workspace 解析本地、SSH/SFTP 或 Agent 支持的文件操作实现。
  3. Explorer 通过文件层按需列出目录；编辑器通过同一抽象读取内容。
  4. 保存远程内容会使用远端状态/冲突处理，因此 UI 可展示冲突对话框。
AI 编程工作流
  1. CodingAgentPanel 通过 codingService 将消息发给 coding Command/Session。
  2. 后端调用已配置的 Engine/Provider，并通过工作区文件/执行目标暴露工具操作。
  3. Build 模式的修改会成为可跟踪 Change 与 Diff，并以可审查的 Change Card 呈现。
  4. 执行前会评估权限规则和命令确认；接受/拒绝/撤销结果将更新历史和审计数据。
SSH 终端与传输工作流
  1. Connection Manager 解析 Profile 元数据，并从密钥环获取凭据。
  2. SSH Pool 在适用时复用已认证物理连接，并为终端/SFTP 打开 Channel。
  3. 终端 UI 通过事件/Service/Command 层中转 xterm 输入输出；SFTP 视图使用文件和传输 Command。
