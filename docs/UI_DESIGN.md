# roc_desk — UI 设计文档（UI/UX Design）

> 本文档定义 roc_desk 的视觉设计系统与各模块界面细节，是 [../DESIGN.md](../DESIGN.md) 功能设计和 [CODE_DESIGN.md](CODE_DESIGN.md) 组件目录之间的桥梁。实现时 `src-web/src/styles/theme.css` 中的 CSS 变量应与本文档「设计令牌」一节一一对应。

---

## 一、设计原则

roc_desk 是运维/开发人员每天长时间使用的生产力工具，不是消费级应用，设计取舍向这三点倾斜：

1. **信息密度优先于留白美观**：日志行、文件列表、终端输出都是高密度文本场景，行高、内边距要克制（参考 VS Code / iTerm2 的紧凑感），不套用移动端 App 常见的大留白卡片风格。
2. **深色优先（Dark-first）**：主要使用场景是终端和代码，默认主题为深色，浅色主题作为同等优先级的第二套（非"阉割版"）。
3. **键盘优先，鼠标为辅**：所有高频操作（切标签、搜索、确认/拒绝 AI 变更、跳转行号）必须有快捷键，鼠标点击是快捷键的补充而非唯一途径，见「十二、快捷键体系」。
4. **状态诚实**：连接中/已连接/重连中/已断开、AI 正在思考/正在写文件、传输进度——这些状态必须持续可见，不能靠用户猜（运维工具里"看起来卡住了"是最容易引发误操作的场景）。

## 二、设计令牌（Design Tokens）

### 2.1 色彩系统

采用语义化 token，不在组件里直接写色值。深色为主设计，浅色按同一色相反向映射。

| Token | 深色值 | 浅色值 | 用途 |
|-------|--------|--------|------|
| `--bg-app` | `#1e1f22` | `#f5f5f7` | 应用最外层背景 |
| `--bg-surface` | `#26282c` | `#ffffff` | 面板/卡片背景（侧边栏、内容区） |
| `--bg-surface-raised` | `#2f3136` | `#ffffff` + 阴影 | 弹窗、下拉菜单 |
| `--bg-hover` | `#33353a` | `#eceef1` | 列表项/按钮悬停 |
| `--bg-selected` | `#3a4a63` | `#dbe7fb` | 选中态（不用纯品牌色铺底，避免刺眼） |
| `--border-default` | `#3a3c41` | `#e2e4e8` | 面板分隔线 |
| `--text-primary` | `#e6e6e6` | `#1b1c1e` | 主文本 |
| `--text-secondary` | `#9a9ca1` | `#6b6d72` | 次要文本（时间戳、路径、计数） |
| `--text-disabled` | `#5c5e63` | `#b0b2b6` | 禁用态 |
| `--accent` | `#4f8cff` | `#3568e0` | 品牌色：主按钮、激活标签、链接 |
| `--success` | `#3fb950` | `#2a9d3f` | 连接成功、已应用变更、只读命令放行 |
| `--warning` | `#d9a441` | `#b8860b` | 重连中、待确认、大文件提示 |
| `--danger` | `#e5534b` | `#cc3b33` | 断开/失败、拒绝变更、高危命令拦截 |
| `--info` | `#58a6ff` | `#3568e0` | 一般提示 |

**语义色使用规则**（与后端状态机对齐，避免颜色滥用）：

| 场景 | 颜色 |
|------|------|
| SSH `connected` | `--success` 圆点 |
| SSH `connecting` / `reconnecting` | `--warning` 圆点 + 呼吸动效 |
| SSH `disconnected` / 出错 | `--danger` 圆点 |
| AI 变更 `pending` | `--warning` 边框（对应 DESIGN.md `FileChangeCard` 的 pending 态） |
| AI 变更 `applied` | `--success` 边框 |
| AI 变更 `rejected` | `--danger` 边框 |
| 高危命令黑名单拦截 | `--danger` 实心背景警示条，不用普通 toast |
| 主机指纹**首次**信任（TOFU） | `--info`（提示性，不代表危险） |
| 主机指纹**变化**（可能 MITM） | `--danger` + 图标强调，弹窗不可通过点击遮罩关闭 |

### 2.2 字体

| Token | 字体 | 用途 |
|-------|------|------|
| `--font-ui` | `"Inter", "Segoe UI", "PingFang SC", sans-serif` | 界面文字（菜单、按钮、表单） |
| `--font-mono` | `"JetBrains Mono", "Cascadia Code", "Consolas", monospace` | 终端、代码编辑器、日志、路径、diff |

字号刻度（基于 4px 网格）：`--text-xs: 11px`（状态栏、徽标）、`--text-sm: 12px`（列表项、次要信息，也是终端/日志默认字号起点）、`--text-base: 13px`（正文默认——注意比常见 Web 应用的 14–16px 更紧凑，符合开发工具惯例）、`--text-lg: 15px`（面板标题）、`--text-xl: 18px`（弹窗标题）。

### 2.3 间距与网格

4px 基础网格：`--space-1: 4px` ~ `--space-8: 32px`。列表行（连接树、SFTP 文件列表、日志结果行）统一 `28px` 行高、`--space-2` 水平内边距，保证信息密度；弹窗/表单用更宽松的 `--space-4`。

### 2.4 圆角与阴影

- `--radius-sm: 4px`（按钮、输入框、Badge）
- `--radius-md: 6px`（卡片、弹窗）
- `--radius-full`（状态圆点、头像）
- 阴影仅用于浮层（下拉菜单、Popover、Dialog），面板之间用 `--border-default` 分隔而非阴影，避免深色主题下阴影糊成一片。

### 2.5 图标

统一使用 `lucide-react`，界面内固定两档：`16px`（行内、按钮内）、`20px`（侧边栏一级导航、工具栏主要动作）。不与其他图标库混用。

## 三、工作区与整体窗口布局

> 本节替换了早期"侧边栏默认=连接树"的方案，改为 VS Code 式的工作区模型（DESIGN.md §3.1）：应用启动先落在工作区选择页，选定后才进入 IDE 布局，Sidebar 默认内容变为 Explorer 文件树。

### 3.1 工作区选择页（应用入口）

应用冷启动、`Ctrl+Shift+O`、或菜单"文件→打开工作区"都落到这一页：

```
┌──────────────────────────────────────────────────────────────────────┐
│                                                                        │
│                           roc_desk                                      │
│                                                                        │
│      ┌─────────────────────┐    ┌─────────────────────────────┐      │
│      │  📁 打开本地文件夹    │    │  🖥 连接远程主机并选择目录     │      │
│      └─────────────────────┘    └─────────────────────────────┘      │
│                                                                        │
│      最近打开的工作区                                                  │
│      ┌────────────────────────────────────────────────────────┐      │
│      │  💻  my-local-app          F:\code\my-local-app          │      │
│      │  🖥  nginx-conf             /etc/nginx  · root@web-01     │      │
│      │  🖥  api-service            ~/app  · root@web-01          │      │
│      │  💻  scratch                 D:\scratch                   │      │
│      └────────────────────────────────────────────────────────┘      │
│                                                                        │
└──────────────────────────────────────────────────────────────────────┘
```

- 两个入口按钮是等权的主操作（同尺寸并排，不做主次强调），因为"打开本地"和"连接远程"是同等常见的场景。
- **最近打开的工作区**列表：本地用 💻、远程用 🖥 图标区分；远程行额外显示主机名（弱化字重、`--text-secondary`），本地行只显示路径。点击整行直接重新打开；远程工作区重新打开时如需重连，行右侧短暂出现连接中的呼吸圆点，连接失败则整行标红并显示"连接失败，[重试] [编辑连接]"而不是静默停在这一页。
- 右键单个最近工作区：「从列表移除」「在新窗口打开」「复制路径」。
- 列表为空（首次使用）时不显示空表格，改为在两个入口按钮下方给一句引导文案。
- 点击"连接远程主机并选择目录"→ 先出现连接选择/新建（复用 §四 的连接档案管理），连接成功后过渡到一个轻量的远程目录选择器（树形，仅需选中一个目录点击"选定此目录作为工作区"，不提供上传下载等完整 SFTP 操作，避免这一步喧宾夺主）。

### 3.2 进入工作区后的整体窗口布局

```
┌──────────────────────────────────────────────────────────────────────┐
│ [my-app ▾] [🖥 终端] [📄 main.rs]                  [📂][🌐][✨ AI工具][+] ─ □ ✕│ 32px Tab Bar
├────────────┬─────────────────────────────────────────────────────────┤
│  Activity  │                                                          │
│  Bar+Tree  │                                                          │
│ 52/220px   │                      内容区（按 activeTab 切换）           │
│ （可折叠） │                                                          │
│            │                                                          │
├────────────┴─────────────────────────────────────────────────────────┤
│ 🖥 web-01·24ms  Explorer: /home/user/app   UTF-8  Ln 12, Col 4  22px │ Status Bar
└──────────────────────────────────────────────────────────────────────┘
```

- **Tab Bar 左端新增"工作区名 ▾"**：点击弹出工作区切换菜单（切到最近工作区 / 打开新工作区 / 在新窗口打开），是 `Ctrl+Shift+O` 的鼠标入口。
- **Tab Bar 右端新增「顶部快捷工具」图标簇**（📂 SFTP / 🌐 浏览器 / ✨ AI工具），常驻可见；AI工具点击后从工作区右侧展开停靠栏，内部统一承载问答和编程能力。
- **Sidebar 默认内容从"连接树"改为 Explorer 文件树**（§3.3），Activity Bar（52px 折叠态的图标条）包含：Explorer / 搜索（`Ctrl+Shift+F` 全工作区搜索）/ 服务器（呼出 §四 的连接档案管理，供打开额外连接或管理已保存主机）/ 设置。折叠态记忆在 `uiStore`。
- **Status Bar** 左侧展示当前工作区的连接状态（远程）或直接展示本地路径（本地），中间展示 Explorer 根路径，右侧展示当前激活编辑器的编码/光标信息。

**最小窗口尺寸**：`960×600`，低于此尺寸 Sidebar 强制折叠为纯图标模式，顶部快捷工具图标簇优先保留、必要时把工作区名收缩为省略号。

### 3.3 Explorer 文件树

```
┌────────────────────────┐
│ MY-APP                  │  ← 工作区名，全大写弱化色，点击回到 3.1 的切换菜单
├────────────────────────┤
│ ▾ src/                  │
│    main.rs ●            │  ← 圆点=未保存（dirty），非 Git 状态
│    api.rs               │
│ ▾ tests/                │
│    api_test.rs          │
│  Cargo.toml              │
│  README.md               │
└────────────────────────┘
```

- 目录懒加载：展开一个目录才发起 `fs_list_dir`，不会一次性拉全树；加载中该行显示细旋转指示器（非整棵树级 Skeleton，避免大项目卡顿感）。
- **单击 = 预览态**：以斜体、`--text-secondary` 色的标签打开（Tab 标题右上角无关闭态之外的视觉重量），再单击其他文件会复用同一个预览标签；**双击 = 固定态**：标签转为正常字重，之后单击其他文件不会顶掉它，与 VS Code 行为一致。
- 文件图标按扩展名区分（复用 `lucide-react` 的语言图标集或纯色几何图标兜底），未保存的文件在文件名后跟一个 6px 实心圆点（`--warning` 色，与 §2.1 语义色一致），不是红色（红色留给错误/危险语义）。
- 右键菜单：新建文件/文件夹、重命名（行内编辑）、删除（二次确认）、复制路径、"在 SFTP 中打开所在目录"（跳到 §六 的自由浏览工具，用于操作 Explorer 未覆盖的相邻路径）。
- 空态（新建的空工作区目录）：显示"此文件夹是空的"+「新建文件」「新建文件夹」按钮，不是空白一片。

### 3.4 顶部快捷工具与 Tab 复用

```
[📂 SFTP] [🌐 浏览器] [✨ AI工具]
```

- SFTP 与浏览器沿用中央工具视图；AI工具不创建中央 Tab，而是在工作区右侧开关停靠栏，保留编辑器和底部终端可见，交互对齐 VS Code 的 Codex 类插件。
- AI工具内不再提供“问答/编程”重复入口：Plan 模式用于普通问答和只读分析，Build 模式用于执行文件修改或命令。
- 悬停 Tooltip 直接显示“AI工具（问答与编程）”，按钮激活态表示右侧栏已打开。
- 编辑器与 AI工具之间使用 4px 可拖动分隔条；左右拖动调整 AI 栏宽度，最小 300px、最大 800px，并记忆上次宽度。

### 3.5 远程文件编辑状态（保存 / 冲突）

对应 DESIGN.md §3.1.4——远程文件在 UI 上必须表现得和本地文件一样可编辑，只是保存路径不同：

- 编辑器标签的 dirty 圆点（同 §3.3 Explorer 的圆点视觉）在按下 `Ctrl+S` 后立即切换为一个短暂的保存中细旋转图标，成功后圆点消失；本地/远程视觉上完全一致，用户不需要关心底层是文件系统写入还是 SFTP 写回。
- 保存失败（断网/权限/冲突）：dirty 圆点变为 `--danger` 色的感叹号，Tab 上出现红色细下划线，同时右下角 Toast 给出具体原因和「重试保存」按钮；编辑器内容绝不清空。
- **冲突弹窗（ConflictDialog）**：保存时检测到远程文件已被外部修改，弹出阻塞式 Dialog（非 Toast，因为这是需要决策的场景）：

```
┌── 远程文件已被修改 ──────────────────────────┐
│  /home/user/app/src/main.rs 在你编辑期间       │
│  已被其他进程修改。                            │
│                                                │
│  [查看差异]   [仍要覆盖]   [另存为副本]        │
└─────────────────────────────────────────────────┘
```

「仍要覆盖」按钮样式弱化（`ghost`），不给默认高亮，逼用户先看一眼差异，除非确实清楚自己在做什么。

## 四、连接管理与远程目录选择

> 定位调整：连接档案管理不再是默认 Sidebar 内容（默认已改为 Explorer，见 §3.3），而是从两处呼出——§3.1 工作区选择页的"连接远程主机并选择目录"入口，或 Activity Bar 的「服务器」图标（打开一个独立的 ConnectionManager 面板，用于管理已保存主机、临时开一个不属于当前工作区的终端/SFTP 连接）。

```
┌────────────────────────┐
│ 🔍 搜索连接…            │
├────────────────────────┤
│ ▾ 生产环境 (3)          │
│    ● web-01   连接中    │  ← 黄色圆点 + 呼吸动效
│    ○ web-02             │  ← 灰色圆点：未连接
│    ● db-01    已连接    │  ← 绿色圆点
│ ▾ 测试环境 (2)          │
│    ○ test-app           │
│    ○ test-db            │
│ + 新建连接                │
└────────────────────────┘
```

- 分组可折叠，标签以 `Badge` 形式挂在连接名右侧（不占单独一行）。
- 右键菜单：连接 / 断开 / 编辑 / 复制 / 移动到分组 / 删除（删除需二次确认，且提示"关联的已保存凭据也将被删除；若该连接正被某个工作区使用，需先说明将影响哪些工作区"）/ **以此连接打开工作区**（从这里直接跳回 §3.1 的远程目录选择器，是工作区选择页入口之外的第二条路径）。
- 新建/编辑连接用 Dialog（非跳转新页面），字段：名称、Host、Port、用户名、认证方式（密码/密钥/Agent，动态切换下方输入项）、分组、标签、跳板机（可选，选择已有连接作为 ProxyJump）。密码/密钥口令输入框默认 `type=password`，带"显示"切换。
- **远程目录选择器（RemoteDirPicker，§3.1 引用）**：连接成功后的轻量树形浏览器，只做单选目录，不含文件列表/上传下载/权限列——即"选根目录"这一步不应该看起来像完整的 SFTP 工具，避免用户在这里就开始做文件操作从而混淆两个入口的职责。底部一行常驻当前选中路径 + 「选定此目录作为工作区」主按钮。

### 4.1 主机指纹确认弹窗（HostKeyDialog）

首次连接（TOFU）与指纹变化两种视觉强度不同，绝不能共用一个"温和"样式：

```
┌── 首次连接（TOFU） ──────────────┐   ┌── ⚠ 主机指纹已变化 ────────────┐
│  ℹ 这是你首次连接该主机           │   │  🛑 安全警告                    │
│                                   │   │  该主机的密钥指纹与已保存的     │
│  host: web-01.example.com        │   │  记录不一致，可能遭遇中间人攻击 │
│  指纹: SHA256:AbCd...             │   │  或主机被重装。                 │
│                                   │   │  旧指纹: SHA256:1234...         │
│  [取消]        [信任并连接]       │   │  新指纹: SHA256:AbCd...         │
└───────────────────────────────────┘   │  [取消连接]   [仍要信任(危险)]   │
                                         └──────────────────────────────────┘
```

- TOFU 弹窗：`--info` 边框，"信任并连接"为默认按钮（Enter 可触发）。
- 指纹变化弹窗：`--danger` 实色标题条，**不设默认高亮按钮**（用户必须显式点击，且"仍要信任"按钮样式弱化、"取消连接"按钮样式强化，防止误触）；点击遮罩或按 Esc 不关闭，必须显式选择。

## 五、SSH 终端模块

```
┌─────────────────────────────────────────────────────────┐
│ [🔍搜索] [A+][A-] [⇅分屏]                    [⚙ 会话设置]│  工具栏 28px
├─────────────────────────────────────────────────────────┤
│ user@web-01:~$ tail -f /var/log/app.log                 │
│ 2026-08-17 10:22:01 INFO  starting worker...             │  等宽字体，默认 13px
│ 2026-08-17 10:22:03 WARN  queue depth high (120)          │
│ █                                                          │  ← 光标，块状，聚焦时实心/失焦时空心
└─────────────────────────────────────────────────────────┘
```

- 终端本身沿用系统惯例（黑底浅字为主色板，可在设置中换主题），不套用应用整体的 `--bg-surface`，因为终端配色是用户强偏好项，独立可配置。
- 搜索（Ctrl+Shift+F）在终端内弹出浮层搜索条，高亮匹配项，不打断输出流。
- 分屏：同一 SSH 连接下可开多个 Shell Channel 并排显示（复用连接池），标题栏显示各自的当前工作目录（若可探测）。
- 断线重连时终端顶部出现一条不可关闭的横幅：`⚠ 连接已断开，3s 后重试(2/5)  [立即重试] [取消]`，重连成功后横幅变为 `✓ 已恢复` 并在 2s 后自动消失。

## 六、SFTP 文件浏览 + 文本查看器

> 定位调整（DESIGN.md §3.1.3/§3.3）：工作区目录的浏览与编辑已由 §3.3 Explorer 承担，本模块是顶部快捷工具之一，专注**工作区之外的路径**——比如临时看看 `/etc/nginx`、批量传输、查看权限。两者共用同一套目录浏览/大文件分级/文本查看器过渡的底层实现，区别只在于打开的默认可编辑性（见下）。

沿用 DESIGN.md §3.3.1 的三阶段过渡设计，此处补充静态视觉规格：

```
┌─────────────────────────────────────────────────────────┐
│ /var/log/nginx/                          [⇅排序][🔍][⚙]  │  路径 + 工具栏
├─────────────────────────────────────────────────────────┤
│ 名称              大小      修改时间        权限          │  表头，可点击排序
│ 📁 archive/        —        08-17 10:00    drwxr-xr-x   │
│ 📄 access.log     12.4MB    08-17 10:22    -rw-r--r--   │
│ 📄 error.log       3.2MB    08-17 09:58    -rw-r--r--   │  ← 悬停行高亮 --bg-hover
├─────────────────────────────────────────────────────────┤
│ 2 目录, 14 文件 · 已选 0                                  │  底部聚合信息
└─────────────────────────────────────────────────────────┘
```

- 双击文件 → 触发 DESIGN.md 中的骨架屏→Monaco 过渡；非文本文件双击 → 弹出下载确认，不尝试预览。
- 拖拽本地文件到列表区域 → 高亮整个内容区边框（`--accent` 2px 虚线）+ 居中提示"释放以上传到 /var/log/nginx/"。
- 传输任务（上传/下载）统一收纳到右下角"传输"浮层面板（类似浏览器下载列表），每项含进度条、速度、剩余时间、取消按钮，任务完成后 5s 自动折叠但不清除记录。
- 文本查看器工具栏图标顺序固定：搜索 → 跳转行 → 编码切换 → 下载 → 新标签打开 → 返回，符合从"就地操作"到"离开当前视图"的从左到右递进逻辑。
- **默认只读，需显式切换为编辑**：经 SFTP 快捷工具打开的文件默认 `readOnly`，工具栏多一个「编辑」按钮，点击后才可写（与 §3.3 Explorer 打开即可编辑相反）——因为 SFTP 场景往往是"顺手看看工作区之外的系统文件"，不应该一言不合就被改掉；编辑后同样走 §3.5 的 dirty 圆点/保存/冲突检测流程，与 Explorer 编辑体验一致，只是进入编辑态需要多一次点击确认意图。

### 6.1 大文件提示条

当文件超过 50MB（DESIGN.md 大文件分级阈值）时，Monaco 上方出现常驻提示条（非可关闭 toast）：

```
ℹ 文件较大（212MB），已启用分页加载，滚动时按需获取内容    [下载到本地][建索引搜索]
```

超过 500MB 时提示条变为 `--warning` 底色，文案改为"文件过大，建议下载到本地或建立索引后搜索"，且默认不再尝试内联预览（需用户主动点击"仍要预览（可能卡顿）"）。

## 九、AI工具右侧停靠栏（问答与编程）

```
┌─────────────┬───────────────────────────┬───────────────────────────┐
│ Explorer    │ 📝Plan  🔨Build  目标:web-01(远程)[更改▾] 模型▾ │ main.rs [⇄Diff][↩]│
│（与全局共享）├───────────────────────────┤                             │
│ 📁 src/     │ 👤 添加一个API路由         │  fn main() {               │
│ ├📄 main.rs●│                             │      println!("Hello");    │
│ ├📄 api.rs +│ 🤖 我来添加路由…            │  }                         │
│ └📄 util.rs │  ⏳ 正在执行 read_file(api.rs) · 1.2s               │
│             │ ┌─────────────────────────┐ │                             │
│ 变更(2)      │ │📄 api.rs         [待确认]│ │  （modified 高亮左侧竖条） │
│  ● main.rs  │ │ [查看Diff][✓应用][✗拒绝]│ │                             │
│  + api.rs   │ └─────────────────────────┘ │                             │
│             │ [📎][📷] 输入消息…    [发送]│                             │
├─────────────┴───────────────────────────┴───────────────────────────┤
│ 模型 DeepSeek-V3 · Token 2.3k/128k · 已修改 2 个文件 · 远程模式：无智能补全│
└─────────────────────────────────────────────────────────────────────┘
```

- **Plan/Build 切换**用 Tab 而非 Toggle，因为两者是完全不同的工作阶段（只读分析 vs 可写执行），Tab 的视觉隔离感更符合心智模型；Build 模式下 Tab 本身带 `--warning` 细边框，持续提醒"当前会修改文件"。
- **左栏就是 §3.3 的 Explorer**，不是独立的另一棵树：在这里点文件、在 Sidebar 点文件是同一份状态，AI 修改过的文件在两处都会显示变更标注。变更文件的标注：`●`=已修改（黄点）、`+`=新增（绿色）、`-`=已删除（红色，文件名加删除线），与 Git 状态图标语义保持一致，降低学习成本。
- **FileChangeCard** 三态配色直接对应 §2.1 语义色（pending=warning 边框、applied=success 边框、rejected=danger 边框），卡片默认折叠 Diff 预览，点击标题展开。
- **目标从下拉选择改为自动绑定+可覆盖**：默认直接显示只读文本"目标: web-01(远程)"（不是可点击的下拉），远程时用 `--warning` 底色强调，本地工作区则显示"目标: 本地"（`--text-secondary`，无强调色，因为本地场景风险较低）；只有点击旁边小字「更改▾」才展开候选连接列表，切到工作区之外的主机——这是刻意做的"不显眼的例外入口"，防止它被当成日常要选的选项，跟 DESIGN.md §3.8.2.1 强调的"防止用户误以为在改本地文件"是同一个风险点在 UI 上的落地，只是现在默认状态已经不需要用户选一遍。
- **远程能力徽标（RemoteCapabilityBadge）**：状态栏常驻"远程模式：无智能补全"（`--text-secondary`，非警示色，因为这是能力边界说明而不是错误），悬停显示 Tooltip："远程工作区暂不支持语言服务器级智能感知（跳转定义/实时诊断/语义补全），编辑器仅提供基础语法高亮。了解原因 →"，点击可跳转到一段简短说明（对应 DESIGN.md §3.8.7）。本地工作区不显示这个徽标。
- **工具调用进度（ToolCallProgress）**：Agent 每次调用工具（`read_file`/`run_command`等）时，对话流中插入一行浅色小字"⏳ 正在执行 read_file(api.rs) · 1.2s"，耗时实时刷新；完成后这行消失或折叠进对应的 `FileChangeCard`。远程目标下这行几乎每次工具调用都会出现（SSH 往返有延迟），本地目标下如果单次调用低于 300ms 则不显示，避免本地场景被无意义的进度提示刷屏。
- **高危命令确认弹窗（CommandConfirmDialog）**：

```
┌── 确认执行命令 ─────────────────────────┐
│  目标主机: web-01 (10.0.0.1)             │  ← 远程时该行用 --warning 底色强调
│  $ systemctl restart nginx               │  ← 命令原文，等宽字体，只读
│                                           │
│  [拒绝]                    [仅本次允许]   │
└───────────────────────────────────────────┘
```

黑名单命中时不出现此弹窗，直接在对话流中插入一条不可操作的系统消息：`🛑 已拦截高危命令：rm -rf /，如需执行请前往终端手动操作`，样式为 `--danger` 实色条，且**不提供任何绕过按钮**。

## 十一、状态、空态与反馈规范

| 场景 | 组件 | 规格 |
|------|------|------|
| 数据加载中（首次） | Skeleton | 与最终内容同形状的骨架屏，不用通用 Spinner 转圈（列表/编辑器场景骨架屏更少跳动感） |
| 局部刷新（已有数据） | 顶部细进度条 | 4px，`--accent`，不遮挡已有内容 |
| 空列表 | EmptyState | 图标 + 一句话说明 + 主要操作按钮（如"暂无连接，[+ 新建连接]"），不用空表格干等 |
| 非阻塞提示 | Toast | 右下角，自动消失（3–5s），成功用 `--success`，一般信息用 `--info` |
| 需要决策 | Dialog | 阻塞式，见 §四/§九 的确认弹窗规范：风险越高，默认按钮越弱化甚至不给默认按钮 |
| 错误 | Toast（可重试）或内联错误态 | 携带 `AppError.kind`，网络类错误提供"重试"按钮，权限类错误提供"查看详情" |

**动效统一规范**：过渡时长 150–250ms（DESIGN.md 已定义的骨架屏↔内容切换为 200ms），统一使用 `ease-out`；用户系统开启"减少动态效果"（`prefers-reduced-motion`）时，所有淡入淡出/骨架屏动画降级为直接切换，呼吸动效（连接中圆点）改为静态。

## 十三、响应式与无障碍

- **窗口缩放**：三栏类布局（编程助手、日志搜索）在窗口宽度 < 1100px 时，右侧栏（代码编辑器/详情面板）改为可通过点击结果行呼出的覆盖层（Overlay），而不是强行压缩三栏导致每栏都不可用。
- **对比度**：所有 `--text-secondary` 在深色/浅色背景下均需满足 WCAG AA（4.5:1）；语义色（success/warning/danger）不能作为传达信息的唯一手段，需配合图标或文字（色觉障碍用户）。
- **键盘可达性**：所有 Dialog 打开时焦点自动移入，Tab 循环限制在 Dialog 内（focus trap），关闭后焦点归还触发元素。
- **终端/编辑器缩放**：字号可通过 `Ctrl+=` / `Ctrl+-` 独立于系统 UI 缩放调整，两者互不影响。

### 15.2 CSS 变量与设计令牌映射

  --font-mono: "JetBrains Mono", "Cascadia Code", "Consolas", monospace;

  /* 字号刻度 — 4px 网格（§2.2） */

  --text-xl: 18px;    /* 弹窗标题 */
